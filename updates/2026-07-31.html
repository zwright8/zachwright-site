Swarm Daily: Parallel Agents Need Separate Identities

Per-agent users, explicit collaboration groups, separate sandboxes, and cross-client policy turn multi-agent concurrency into an identity-boundary problem.

The Big Thing

Parallel agents are becoming a normal execution shape, but “same container” is not the same as “same trust domain.”

Vercel’s new Sandbox support lets multiple agents share one sandbox while running as separate Linux users. Each gets a private home directory; collaboration is an explicit group with a shared workspace. That is a better default than cloning a process and hoping permissions sort themselves out.

Cloudflare’s Sandbox guidance draws the boundary even more sharply: sessions share filesystem and process space, so sessions are not a security boundary. Use a separate sandbox when users, credentials, or untrusted work must stay apart. GitHub is applying the same logic to policy: managed settings now follow Copilot from CLI and VS Code into the Copilot app and cloud-agent tasks.

  • Vercel Sandbox adds per-agent Linux users and opt-in shared groups: https://vercel.com/changelog/run-multiple-isolated-agents-in-a-single-sandbox
  • Cloudflare documents that sessions share files and processes and recommends separate sandboxes for separate users: https://developers.cloudflare.com/sandbox/concepts/sessions/
  • GitHub’s managed settings now cover the Copilot app and cloud agent as well as existing clients: https://github.blog/changelog/2026-07-27-enterprise-managed-settings-now-apply-to-the-github-copilot-app/

Code & Tools

  1. Vercel Sandbox createUser / createGroup - give each agent its own Linux identity, then create the smallest shared directory needed for handoffs. https://vercel.com/changelog/run-multiple-isolated-agents-in-a-single-sandbox
  2. Cloudflare Sandbox getSandbox(binding, `user-${userId}`) - map user or tenant identity to the sandbox ID when filesystem, memory, network, or data must be isolated. https://developers.cloudflare.com/sandbox/concepts/containers/
  3. Cloudflare explicit sessions - use session IDs to separate shell state, but do not treat them as a security boundary; sessions still share the sandbox’s files and processes. https://developers.cloudflare.com/sandbox/concepts/sessions/
  4. GitHub copilot/managed-settings.json - centralize plugin, marketplace, approval-bypass, and model defaults across the clients that can act on your repositories. https://github.blog/changelog/2026-07-27-enterprise-managed-settings-now-apply-to-the-github-copilot-app/
  5. Turborepo and Vercel Remote Cache OIDC - bind CI cache access to workflow identity instead of handing every runner a static token. https://vercel.com/changelog/turborepo-and-remote-cache-now-support-openid-connect-oidc

Tech Impact

  • Parallelism without identity is shared blast radius. Test cross-agent read/write attempts, credential exposure, and shared-directory writes as boundary failures—not as bugs discovered after a merge.
  • Shared workspaces should be allowlisted artifacts. Keep secrets, package caches, and generated credentials outside the collaboration group. The default should be private; handoff should be explicit.
  • Containment belongs in evaluation too. The recent Hugging Face model-evaluation incident shows why agents with broad cyber capability need bounded credentials, isolated environments, and an observable stop path before they touch real infrastructure: OpenAI’s incident report.

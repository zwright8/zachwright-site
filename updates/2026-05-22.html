Swarm Daily: Agent Sandboxes Are Becoming the Runtime Boundary

Google Managed Agents, Claude self-hosted sandboxes, Vercel microVMs, and Copilot audit APIs are making agent execution a policy boundary.

The Big Thing

Agent sandboxes are becoming the runtime boundary: the useful product is no longer just a smarter loop, it is the isolated place where that loop can touch files, tools, networks, and secrets.

Why it matters: operators are past the demo question of whether an agent can call a tool. The production question is where the tool ran, what it could reach, how credentials were brokered, and whether the session can be resumed or audited.

  • Google launched Managed Agents in the Gemini API, letting developers spin up an Antigravity-powered agent that reasons, uses tools, executes code in an isolated Linux environment, and carries resumable session state. https://blog.google/innovation-and-ai/technology/developers-tools/managed-agents-gemini-api/
  • Google's I/O developer stack pushes the same boundary through Antigravity 2.0, the Antigravity SDK, Gemini Enterprise integration, AI Studio export, and Android test-track publishing. https://blog.google/innovation-and-ai/technology/developers-tools/google-io-2026-developer-highlights/
  • Anthropic added self-hosted sandboxes and MCP tunnels for Claude Managed Agents, so the managed loop can reach private systems while tool execution stays inside customer-controlled infrastructure. https://claude.com/blog/claude-managed-agents-updates
  • Vercel now runs Claude Managed Agents inside per-session Firecracker microVMs with a function control plane, credential brokering at the firewall, and deny-by-default egress. https://vercel.com/changelog/run-claude-managed-agents-with-vercel-sandbox

Code & Tools

  1. Gemini API Managed Agents - turns the Antigravity harness, custom instructions, skills, files, tools, and resumable execution into an API surface. https://blog.google/innovation-and-ai/technology/developers-tools/managed-agents-gemini-api/
  2. Claude Managed Agents self-hosted sandboxes - splits managed orchestration from customer-controlled execution and private MCP connectivity. https://claude.com/blog/claude-managed-agents-updates
  3. Vercel Sandbox CMA guide - shows the control-plane/compute-plane pattern: webhook starts the session, one sandbox attaches, executes tool calls, posts results, and exits. https://vercel.com/kb/guide/run-claude-managed-agent-tools-with-vercel-sandbox
  4. Copilot cloud agent Actions fixes - adds a Fix with Copilot handoff from failed workflow logs; the agent investigates, pushes a fix, and tags the operator for review. https://github.blog/changelog/2026-05-18-one-click-fixes-for-failing-actions-with-copilot-cloud-agent/
  5. Copilot cloud agent configuration API - exposes MCP servers, enabled tools, Actions policy, and firewall configuration for repository-scale audit. https://github.blog/changelog/2026-05-18-audit-repository-copilot-cloud-agent-configuration-via-the-rest-api/

Tech Impact

  • Agent runtime becomes security architecture. The durable primitive is the execution boundary: filesystem, tools, network, branch write access, and session state.
  • Secrets move out of the sandbox. Credential brokering at the network edge is cleaner than copying long-lived keys into every agent environment.
  • Audit needs to join config and behavior. Tool catalogs, MCP endpoints, model choices, egress policy, and CI write permissions belong in the same review loop.
  • Cheap isolation changes delegation habits. When a sandbox is disposable enough, every failed check, review batch, and planning branch can get its own constrained agent run.

Meme of the Day

Hey, As Long As It Works. - the old runtime strategy before every agent vendor started shipping microVMs, firewall brokers, and audit APIs.

Swarm Daily: Agent Work Needs a Harness Benchmark

Agent scaffolding, tool interfaces, sandboxes, and turn budgets can dominate cost and reliability, so operators need a benchmark for the full harness.

The Big Thing

The model is only one variable. The agent harness is becoming the performance surface.

A controlled study published August 9 ran one fixed software task across seven agent scaffoldings and five language models, then verified the repository state instead of trusting the agent's self-report. The dominant effect was the scaffolding: in the tested task, CLI-only runs were 5x to 28x cheaper than the MCP-enabled scaffoldings, and paired MCP-to-CLI cost ratios ranged from 0.43x to 29x. The result is not a universal MCP verdict. It is a warning against treating tool-interface benchmarks as portable facts.

The platform response is already visible. Vercel's HarnessAgent puts Claude Code, Codex, Deep Agents, OpenCode, and Pi behind a common agent interface. That makes the runtime swappable, but it also makes the runtime a production dependency. Change the harness and you may change context handling, permissions, retries, compaction, sandbox behavior, and the amount of work required to reach the same artifact.

Run a harness benchmark before you optimize the prompt. Pin the model, harness, tool interface, sandbox, permission mode, and turn budget. Measure cost, latency, completion, retries, changed files, and human review effort. Validate the output in the repository or application. A transcript that sounds finished is not a finished run.

  • The August 9 controlled comparison measured MCP and CLI use across seven agent scaffoldings and five models, with the scaffold driving cost and completion behavior: https://arxiv.org/abs/2608.08654
  • Vercel's HarnessAgent normalizes established harnesses including Claude Code, Codex, Deep Agents, OpenCode, and Pi behind one interface: https://vercel.com/changelog/program-agent-harnesses-with-ai-sdk

Code & Tools

  1. AI SDK HarnessAgent - use a common generate/stream surface while swapping the harness underneath; keep the adapter, sandbox, and permission settings in the benchmark record. https://vercel.com/changelog/program-agent-harnesses-with-ai-sdk
  2. OpenAI Agents SDK SandboxAgent - run file inspection, shell commands, and edits inside a controlled sandbox, then use snapshots and rehydration when the original container fails or expires. https://openai.com/index/the-next-evolution-of-the-agents-sdk/
  3. GitHub Copilot sandboxes - compare local isolation with ephemeral cloud execution; inherit cloud-agent policies and record whether session state must survive across machines. https://docs.github.com/en/copilot/concepts/about-cloud-and-local-sandboxes
  4. Claude Code CLI controls - use --output-format json, --max-turns, explicit permission modes, and resume/continue to make scripted harness runs bounded and inspectable. https://docs.anthropic.com/en/docs/claude-code/cli-usage

Tech Impact

  • Benchmarks move up a layer. “Model X costs less” is incomplete without the scaffold, tools, sandbox, and failure policy that produced the number.
  • Portability has a measurement tax. A common harness interface makes switching easier, but every adapter can change context, retries, approvals, and review burden.
  • Safety controls are performance variables. Sandboxes, permission prompts, and turn caps protect the system while also changing completion time and success rate; record them as first-class run metadata.

Swarm Daily: Agent Work Needs an Intent Envelope

Issue trackers are becoming the agent control surface, carrying owners, delegates, branches, confidence, rationale, and review paths as one handoff contract.

The Big Thing

The unit of agent work is becoming an issue intent, not a prompt.

GitHub Issues now lets automations suggest or apply supported changes with a confidence level and a rationale. Medium- and low-confidence actions can wait as searchable suggestions, while an operator decides what crosses the threshold. That is a small feature with a large implication: triage metadata is becoming a reviewable execution surface.

GitHub’s Copilot cloud agent for Linear makes the other half explicit. Assign an issue to the agent, choose the model and custom agent, set the base and working branches, and steer the session through comments. Linear keeps the human as the primary owner while the agent acts as a delegate. The work item now carries the operating context instead of handing the agent a naked sentence and hoping the runtime fills in the blanks.

Define that context as an intent envelope: accountable owner, delegated agent, allowed mutation, repository and branch, confidence threshold, and review destination. If those fields are absent, the agent is not under-specified; the workflow is.

  • GitHub Issues adds approvals, confidence, rationale, and searchable suggestions for agent automations: https://github.blog/changelog/2026-07-23-agent-automation-controls-in-github-issues-in-public-preview/
  • Copilot cloud agent for Linear adds model, custom-agent, branch, and live-steering controls to delegated issues: https://github.blog/changelog/2026-07-23-copilot-cloud-agent-for-linear-is-now-generally-available/
  • Linear’s agent model keeps the human accountable while agents receive delegated issues, guidance, and scoped access: https://linear.app/docs/agents-in-linear

Code & Tools

  1. GitHub issue intents - enable issue-intents: true for supported agentic workflow outputs, then use has:suggestions to find changes waiting for review. Keep the action set narrow: labels, fields, type, close, and assignment. https://github.blog/changelog/2026-07-23-agent-automation-controls-in-github-issues-in-public-preview/
  2. Copilot for Linear - set the model, custom agent, base branch, working branch, and team guidance before delegating an issue; mention Copilot in a comment to steer a run already in flight. https://github.blog/changelog/2026-07-23-copilot-cloud-agent-for-linear-is-now-generally-available/
  3. Linear agent scopes - request app:assignable and app:mentionable only when the integration needs to be delegated work or invoked from issue surfaces. https://linear.app/developers/agents
  4. AI SDK 7 HarnessAgent - keep the product interface stable while swapping Codex, Claude Code, Deep Agents, OpenCode, or Pi underneath it. https://vercel.com/changelog/ai-sdk-7
  5. Cloudflare Code Mode runtime - call search(), describe(), and execute() from a non-AI-SDK host, and preserve requiresApproval before executing protected connector methods. https://developers.cloudflare.com/changelog/post/2026-07-22-mcp-codemode-updates/

Tech Impact

  • The work item becomes the integration boundary. Prompts can change, but the issue needs to carry the constraints that make a run attributable and reviewable.
  • Confidence is routing policy, not trust. High-confidence metadata edits can flow; low-confidence changes should remain suggestions with an explicit owner and review destination.
  • Portability will be won at the envelope layer. Normalized intents, scoped permissions, and stable handoffs matter more than picking one permanent agent harness.

Swarm Daily: Agents Need a Capability Registry

ARD registries, ranked discovery, on-demand skills, and governed activations turn an agent's toolset into a runtime capability layer.

The Big Thing

The next agent bottleneck is not adding more tools. It is finding the right capability at runtime, verifying it, and loading only what the task requires.

Google's Agentic Resource Discovery specification gives that problem a protocol-shaped home: publish, discover, and verify tools, skills, agents, and other callable resources across organizational boundaries. The important shift is architectural. An agent no longer needs every integration wired into its host before it can start; it needs a trusted answer to what is available now.

GitHub Agent Finder is the first operator-friendly version of that loop. Point Copilot at a public or private registry, describe the task, and it returns ranked capabilities it can pull in on demand. Managed settings scope what may be discovered, and there is no silent installation. Cloudflare's Agent Skills show the runtime pattern underneath: advertise a cheap catalog, activate a matching skill, load its resources, and optionally run a bounded script.

Treat the registry as production infrastructure. Allowlist sources, review publishers, budget context, and log every activation. “Install a plugin” is becoming four separate operations: discover, verify, activate, and observe.

  • Google and industry partners announced ARD, an open specification for publishing, discovering, and verifying AI capabilities: https://developers.googleblog.com/announcing-the-agentic-resource-discovery-specification/
  • GitHub Agent Finder searches a chosen catalog, ranks matches, respects managed settings, and does not auto-install resources: https://github.blog/changelog/2026-06-17-agent-finder-for-github-copilot-now-available/
  • Cloudflare Agent Skills load instructions, resources, and scripts on demand instead of bloating every prompt: https://developers.cloudflare.com/agents/runtime/execution/agent-skills/

Code & Tools

  1. GitHub Agent Finder + ARD - search a selected registry for MCP servers, skills, canvases, agents, and tools; keep the returned match separate from the approval to connect it. https://github.blog/changelog/2026-06-17-agent-finder-for-github-copilot-now-available/
  2. Cloudflare SkillRegistry - expose activate_skill, read_skill_resource, and optional run_skill_script; use source ordering and allowlists to control which duplicate wins. https://developers.cloudflare.com/agents/runtime/execution/agent-skills/
  3. GitHub Agent Apps - install bounded agents from the Marketplace, admin-enable them, then invoke them from issues, pull requests, or the Agents UI. https://github.blog/changelog/2026-06-02-extend-github-with-agent-apps/
  4. Vercel coding-agent plugin - rank, deduplicate, and budget project-aware skills, then use PostToolUse validation to catch stale APIs as the agent works. https://vercel.com/changelog/introducing-vercel-plugin-for-coding-agents
  5. Chrome DevTools for agents - use MCP, CLI batching, agent skills, Lighthouse audits, and third-party developer tools to give agents bounded runtime context. https://developer.chrome.com/blog/devtools-for-agents-v1

Tech Impact

  • Discovery becomes a supply-chain boundary. Registry identity, publisher verification, allowlists, and revocation matter as much as tool quality.
  • Context becomes an operating budget. Keep catalogs cheap; load full instructions, scripts, and connectors only after a task match.
  • Governance must follow the capability. A plugin policy that covers the IDE but not the cloud agent is not a policy; it is a gap.

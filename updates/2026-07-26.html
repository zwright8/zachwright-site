Swarm Daily: MCP Needs a Stateless Core

MCP's July 28 revision removes protocol sessions, making remote tool transport horizontally scalable while moving state into explicit application handles and conformance tests.

The Big Thing

The next MCP revision removes a hidden infrastructure tax: remote tool servers no longer need protocol sessions, sticky routing, or a shared session store just to handle ordinary calls.

The MCP `2026-07-28` release candidate removes the initialize/initialized handshake and Mcp-Session-Id. A request can land on any healthy instance behind a normal load balancer, while gateways can route and observe from protocol headers. This is a transport simplification, not a state deletion: a browser, basket, or long-running job still needs an explicit application handle that the model passes between calls.

GitHub's MCP Server is already running the new shape. It removed Redis session reads and writes, moved logging and secret-scanning inspection to guaranteed HTTP headers, and upgraded elicitation for separate request/response steps. The operator move is clear: migrate the wire contract, then prove it with conformance tests.

  • MCP's release candidate makes the core stateless, adds extensions for MCP Apps and Tasks, hardens authorization, and sets a formal deprecation policy. Final publication is scheduled for July 28. https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/
  • GitHub MCP Server supports the revision early, eliminating Redis sessions and deep packet inspection while adding official conformance-test guidance. https://github.blog/changelog/2026-07-23-github-mcp-server-supports-the-next-mcp-specification/

Code & Tools

  1. GitHub MCP Server - study the migration pattern: remove protocol-session storage, read stable headers for logging and secret scanning, and keep old/new clients compatible through the official Go SDK. https://github.blog/changelog/2026-07-23-github-mcp-server-supports-the-next-mcp-specification/
  2. MCP Conformance Test Framework - run client and server scenarios in CI, keep expected failures explicit, and make protocol upgrades fail loudly instead of discovering them in production. https://github.com/modelcontextprotocol/conformance
  3. MCP C# SDK stateless mode - use stateless transport for `2026-07-28`, then carry required state as application data; subscriptions and unsolicited server-to-client requests remain stateful concerns. https://csharp.sdk.modelcontextprotocol.io/concepts/stateless/stateless.html
  4. Official MCP Go SDK - use the maintained SDK path that GitHub's server has adopted, rather than hand-rolling the new transport semantics. https://github.com/modelcontextprotocol/go-sdk

Tech Impact

  • Stateless transport moves state into the product contract. IDs for browsers, carts, jobs, and approvals now need ownership, expiry, replay rules, and observability.
  • Gateways get simpler and more useful. Round-robin routing, header-based policy, cacheable tool discovery, and ordinary HTTP tracing reduce special infrastructure, but auth assumptions must be re-audited.
  • Conformance becomes the release gate. SDK compatibility is a starting claim; scenario results are the evidence that a client or server survives the breaking revision.

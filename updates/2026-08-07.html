Swarm Daily: Agent Sessions Need a Durable Wire

Persistent connections, continuation handles, durable background runs, and session budgets turn long-running agent work into an operator-owned protocol.

The Big Thing

Long-running agent work is becoming a session protocol, not a chain of requests.

Vercel AI Gateway’s Responses WebSocket keeps a persistent connection open and continues each turn with new input plus previous_response_id, instead of resending the full context over a fresh HTTP request. Vercel cites up to roughly 40% faster end-to-end execution for agentic rollouts with 20 or more tool calls. The optimization is useful, but the operating shift is bigger: the continuation handle is now part of the work.

Cloudflare’s Agents SDK makes the other half durable. Detached sub-agent runs return handles, persist progress and milestones, survive deploys and evictions, and expose maxBudgetMs and cancellation. Its runTurn facade makes wait, submit, and stream explicit modes. The live wire can carry interaction while durable state owns recovery, bounded execution, and what happens after the socket disappears.

Design the session before optimizing the prompt. Every long run needs an owner, a non-guessable handle, a continuation policy, a budget, a cancellation path, a retention limit, and a reconnect test. If those are absent, a dropped connection is not a network edge case; it is an undefined job state.

  • AI Gateway supports persistent WebSocket Responses sessions with previous_response_id, store:false, and Zero Data Retention compatibility: https://vercel.com/changelog/websocket-support-for-openai-responses-api-live-on-ai-gateway
  • Cloudflare detached sub-agents provide durable handles, progress, milestones, budgets, and cancellation across deploys and evictions: https://developers.cloudflare.com/changelog/product/agents/
  • OpenAI’s WebSocket Mode documents the persistent connection and event protocol for multi-turn Responses API sessions: https://developers.openai.com/api/docs/guides/websocket-mode

Code & Tools

  1. AI Gateway Responses WebSocket - connect to wss://ai-gateway.vercel.sh/v1/responses, send response.create, and continue with the prior response ID; test reconnect and stale-handle behavior explicitly. https://vercel.com/changelog/websocket-support-for-openai-responses-api-live-on-ai-gateway
  2. Cloudflare runAgentTool - dispatch detached work with a returned handle, bounded maxBudgetMs, progress, and a durable finish callback that survives eviction. https://developers.cloudflare.com/changelog/product/agents/
  3. Cloudflare runTurn - make admission explicit with mode: "wait", "submit", or "stream" instead of hiding queueing and continuation behind separate code paths. https://developers.cloudflare.com/changelog/product/agents/
  4. GitHub Copilot session limits - use --max-ai-credits for noninteractive runs or /limits in the CLI; the cap covers model calls, sub-agents, and compaction. https://github.blog/changelog/2026-07-01-set-ai-credit-session-limits-in-copilot-cli-and-sdk/
  5. Copilot usage records streaming - send prompts, responses, and tool calls to an event collector or SIEM so session state is visible outside the client that owns the connection. https://github.blog/changelog/2026-07-02-copilot-agent-session-streaming-is-now-in-public-preview/

Tech Impact

  • The session handle becomes the authority. Scope it, make it non-guessable and revocable, tie it to an owner and budget, and reject stale continuations.
  • Live transport and durable state split apart. A dropped socket should not erase the run, while a stale handle should not resurrect it forever.
  • Cost follows the session. Tool calls, sub-agents, retries, and compaction spend inside one run, so a per-prompt estimate is no longer a sufficient budget.

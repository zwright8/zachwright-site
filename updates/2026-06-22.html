Swarm Daily: Tools Need a Registry Card

ARD, GitHub Agent Finder, Hugging Face Discover, skills.sh, MCP Registry, and Copilot managed settings move agent capabilities from preloaded configs to scoped discovery.

The Big Thing

The useful shift is that agent capability selection is moving out of static config and prompt stuffing. The next operating surface is a governed registry: searchable enough for intent, explicit enough for trust, and constrained enough that discovery does not become silent installation.

Google announced Agentic Resource Discovery as an open specification for publishing, discovering, and verifying tools, skills, agents, MCP servers, A2A agents, APIs, and callable services. The model is simple: publishers host catalogs under their own domains, registries index those catalogs, and clients resolve the right capability at runtime with publisher and trust metadata attached.

  • ARD makes ai-catalog.json and registry search the discovery layer in front of MCP, Skills, A2A, and ordinary APIs. https://developers.googleblog.com/announcing-the-agentic-resource-discovery-specification/
  • GitHub Agent Finder is the first operator-facing proof point: Copilot can search a chosen registry, rank matching AI resources, and load only what the task calls for. https://github.blog/changelog/2026-06-17-agent-finder-for-github-copilot-now-available/
  • The ARD spec repo is already concrete enough to matter: schemas, OpenAPI definitions, ADRs, conformance tooling, and draft v0.9 status make this an implementation target, not just ecosystem language. https://github.com/ards-project/ard-spec

Code & Tools

  1. Agentic Resource Discovery - publish capabilities under a domain, index them through registries, and make publisher identity plus verification metadata part of the handoff. https://developers.googleblog.com/announcing-the-agentic-resource-discovery-specification/
  2. GitHub Agent Finder - point Copilot at a public or private registry, search in plain language, and keep install approval separate from discovery. https://github.blog/changelog/2026-06-17-agent-finder-for-github-copilot-now-available/
  3. Hugging Face Discover - search Spaces, Skills, and MCP servers through ARD, filter for running Spaces, and return skill or MCP server-card artifacts that clients can load normally. https://huggingface.co/blog/agentic-resource-discovery-launch
  4. hf-discover - use the CLI/server to query ARD registries, navigate /.well-known/ai-catalog.json, emit JSON, and test referral-aware discovery flows. https://github.com/huggingface/hf-discover
  5. skills.sh API - query more than 600,000 skills with project-scoped Vercel OIDC, security-audit metadata, and no long-lived shared secret. https://vercel.com/changelog/the-skills-sh-api-is-now-available

Tech Impact

  • Context windows stop being tool inventories. The registry should carry the catalog; the model should receive only the capability the current job needs.
  • Discovery policy becomes an enterprise control. Decide which registries are allowed, which publishers are trusted, and which clients may connect before the agent starts searching.
  • Runtime readiness becomes routing data. A tool that is listed but not currently runnable is noise; readiness, version, protocol, and compliance tags need to be first-class fields.
  • Bad metadata becomes production risk. Thin descriptions, stale endpoints, spoofed publishers, and unbounded referrals will route agents into the wrong tool with confidence.

Meme of the Day

Standards. - because every solution to discovery eventually becomes one more thing operators have to catalog.

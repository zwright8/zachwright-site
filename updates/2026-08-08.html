Swarm Daily: Agent Workspaces Need an Egress Gate

Per-agent sandboxes, reviewed patches, temporary accounts, and claim paths make workspace egress the new control surface for agent work.

The Big Thing

Agent execution is moving into disposable workspaces; the production boundary is how work gets out.

Vercel’s Herdr integration gives Claude Code, Codex, and OpenCode separate Sandbox microVMs. The plugin shows the file set before upload, returns machine-readable JSON, and brings changes back as a Git patch that you apply only when you choose. Even deletion is an explicit human action: type DELETE.

Cloudflare’s temporary-account flow applies the same idea to deployment. An agent or platform can deploy and verify a generated Worker before the user authenticates, then expose a preview URL and a time-limited claim URL. The backend keeps temporary credentials; the user decides whether the preview becomes owned infrastructure.

That is an egress gate. Treat sandbox creation, input manifest, patch application, deployment target, claim, retention, and deletion as separate transitions. Isolation without a narrow exit is just a remote filesystem with better branding.

  • Herdr runs each terminal agent in its own Vercel Sandbox, with dry-run uploads, JSON actions, patch apply, and human-confirmed deletion: https://vercel.com/changelog/give-every-agent-in-herdr-its-own-vercel-sandbox
  • Cloudflare temporary accounts support preview, redeploy, and claim while keeping temporary credentials in the backend: https://developers.cloudflare.com/workers/platform/claim-deployments/

Code & Tools

  1. Herdr Vercel Sandbox plugin - install with herdr plugin install vercel-labs/herdr-vercel-sandbox-plugin; make the first call a dry run, then use apply to receive a Git patch instead of mutating the host directly. https://vercel.com/changelog/give-every-agent-in-herdr-its-own-vercel-sandbox
  2. wrangler deploy --temporary - let an unauthenticated agent deploy a preview, then hand the intended owner a claim URL; do not treat the temporary account as production. https://developers.cloudflare.com/workers/platform/claim-deployments/
  3. Sandbox.fork() - branch from a saved snapshot for parallel agent variants, tenant copies, or test matrices; remember the fork sees the latest saved state, not live memory. https://vercel.com/changelog/vercel-sandbox-supports-forking
  4. Cloudflare Sandbox SDK 1.0 preview - use sandbox.exec() with explicit handles for output, waiting, and signals; each launch is independent, so hidden shell state does not leak across steps. https://developers.cloudflare.com/changelog/product-group/ai/
  5. AI Search public endpoints - put a custom domain, authentication, and instance namespace in front of retrieval when a prototype becomes a user-facing service. https://developers.cloudflare.com/changelog/post/2026-08-06-public-endpoint-custom-domains-and-namespaces/

Tech Impact

  • The important control is egress. Define exactly which files, credentials, URLs, and mutations can leave the workspace, then make the boundary reviewable.
  • Disposable compute changes retention math. Snapshots, temporary accounts, patches, and claim links all need owners, expiry, and cleanup paths.
  • Review is shifting from keystrokes to crossings. The useful record is the input manifest, diff, deploy target, claim event, and deletion event.

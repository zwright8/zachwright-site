Swarm Daily: Websites Need an Agent Readiness Check

Agent-readiness scans, crawler controls, and machine-readable delivery turn a website into an operator-owned interface for automated visitors.

The Big Thing

Your website is becoming an API for machine visitors.

Cloudflare's Agent Readiness report now scores a URL across basic web presence, discoverability, content accessibility, bot access control, protocol discovery, and commerce. That is a useful shift in framing: “can an agent use this site?” becomes a launch check with named failure modes, not a vague SEO question.

The operator move is to add a machine-interface preflight to every important surface. Check that the page can be found, parsed, and traversed; expose the right protocol or action path; and decide which crawlers can use which content. Google-Extended is deliberately separate from Google Search, while OpenAI's crawler guidance distinguishes search discovery from ad landing-page validation. Access is no longer one global allow/deny switch.

Run the scan in CI or a scheduled job, keep the score next to uptime and Core Web Vitals, and fix the lowest-scoring surface before you invite more agents to it.

  • Cloudflare's URL Scanner adds six Agent Readiness categories and an API path to retrieve the scores: https://developers.cloudflare.com/changelog/post/2026-05-12-url-scanner-report-agent-readiness/
  • Google-Extended lets publishers control eligible Gemini training and grounding without removing content from Google Search: https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers
  • OpenAI's crawler guidance separates OAI-SearchBot from OAI-AdsBot and calls out both robots.txt and firewall verification: https://help.openai.com/en/articles/20001243-advertiser-guidance-for-allowing-openai-web-crawlers

Code & Tools

  1. URL Scanner Agent Readiness - call the API with agentReadiness: true and store the result as a regression artifact for important URLs. https://developers.cloudflare.com/api/resources/url_scanner/subresources/scans/methods/create/
  2. AI Crawl Control robots.txt analytics - inspect crawler identity, response codes, disallowed-path attempts, and referrer trends instead of assuming your directives are followed. https://developers.cloudflare.com/changelog/26/
  3. OAI-SearchBot and OAI-AdsBot - test provider-specific robots.txt rules and firewall allowlists separately; search discovery and ad validation are different jobs. https://help.openai.com/en/articles/20001243-advertiser-guidance-for-allowing-openai-web-crawlers
  4. Google-Extended - use the robots.txt token when you want to control Gemini training or grounding without blocking Google Search. https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers
  5. Robots meta and X-Robots-Tag - use page-level and text-level controls for content that should not be indexed or surfaced in AI Search features. https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag

Tech Impact

  • SEO becomes one consumer of a wider machine-interface contract. Protocol discovery, accessible output, and transaction paths now belong in launch criteria.
  • A 200 response is not enough. The right crawler, content type, payload size, and referral path matter more than raw crawl volume.
  • Machine delivery can be optimized like an API. Track response codes, crawler mix, content size, and task completion before widening access.
